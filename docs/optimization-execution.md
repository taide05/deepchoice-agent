# 整体质量优化：推进与维修规则

更新：2026-10-10。范围见[路线](current-roadmap.md)，度量见[评估协议](product-effectiveness-optimization.md)，
事实和余额见[状态](o1-execution-status.md)。本页取代旧单场景逐次停线方式。

## 1. 按共同原因形成修复批次

当前八小时计划已结案，不能照旧 N1–N4、计时卡或研究额度继续执行。
接手顺序和跨会话教训见[复盘](agent-development-lessons.md)。
沿原始需求到公开结果，横向列出检索供给、筛选、证据链、模型判断、绑定/引用、
自审、渲染各处可观察的损失与实际消费者；并列记录多个阻断，标明已证实与未知。
不要只停在第一个损失，也不要只围绕旧失败题反推。旧题只能查历史结论。

每个修复包先写拟删/并的处理、保留消费者和边界、预期报告收益及反例。
默认删并重复处理；新增规则、提示、分支或调用须证明共性阻断无法更简单解决。
实施中用固定材料和相关测试；一包完成并冻结身份后，再按已获授权的全新题集
集中运行完整报告。结构回放、测试数、净删行数都不等于内容收益。
连续两种实质方案无收益就停止该机制、重看责任划分。

## 2. 工作量、验证与外呼

- 改动期间运行最小相关回归与固定输入回放。代码、测试和运行条件冻结后完成受影响
  检查、完整工程套件及契约要求的独立复核。仅文档或结果记录变化可沿用仍有效的通过记录。
- 代码精简是主线，相关测试同包删并。保留独立的安全、事实、预算、恢复、兼容负例；
  不靠隐藏参数或削弱断言制造测试数下降。
- 先核实一条实际 durable 链路的运行、可查询结果和有据回答，再决定扩大样本或并发；
  并发若只用于加速采集，不能成为内容尚未通过时的前置大批次。明确将运行成功与回答成功
  分开记账，避免测量控制器维修吞掉报告诊断时间。
- 真实报告须在新题、rubric、候选身份、来源政策、运行顺序、额度与停止线预冻结后，
  一次集中运行。任何 Codex 时期题目或改写均不进入新内容验收。
- 上一轮完整研究从 230 到 240，新增 10/10 已结算，最终 24 封存。
  旧付费授权不提供新额度；新外呼需当前用户明确上限。未知成本不记零。
- 一旦新委托已覆盖范围、额度与停止线，普通实施、测试、本地提交和该范围内准入连续推进；
  只在真实越界或安全/身份/未知提交等阻断时请求决定。阶段检查点简报用户可见结果、
  已用时间与外呼成本、剩余阻断和下一动作，不重复展示旧计划充当进展。
- 发生安全、预算、租约权威、身份漂移或未知提交时暂停新准入，先对账；
  外部来源故障与内容失败分别记录，不能重跑覆盖失败。

## 3. 失败、维修与恢复

| 情况 | 处理 |
|---|---|
| 内容错误/关键缺答/引用错配 | 记录影响及共性原因；开发批按预定矩阵完成后决定候选，不把一个失败扩展成项目全败 |
| 一般表达问题 | 记录；不单独开新实现轮、不抬高冻结门槛 |
| 可归类的外部故障 | 区分HTTP与逻辑结果，遵守限流/超时并保留降级；不重复整例来覆盖失败 |
| 运行/采集实现缺陷 | 停止相关准入、保存证据并维修；必要故障测试和独立复核后，按新身份/预算决定未来运行 |
| 安全、预算、身份、权威丢失或未知提交 | 停止新准入，核对任务/预算与两库，不吞异常继续；收齐证据后处理根因 |
| 数据集或评审有缺陷 | 先判是否影响决定，保留原结果；须修订则版本化，不能为了低分改题或改标准 |
| 没有净改善 | 放弃该方案、简化或重新定位；保留有效成果和失败证据，连续无收益规则见上 |

中断后依次读Git状态→当前文档→准入记录→task/run终态与服务归属→配对数据库→兼容身份
和预算。未知提交先对账，collector缺输出不代表未提交；不能重启旧停止根或直接写生命周期表。
主机/助手中断不清空研究账本。恢复、服务停机、备份保留原授权边界。

## 4. 授权与独立复核

用户已授权的普通离线工作与本地提交无需逐步请示；越过当前委托、付费研究、
新增数据外传、供应商、发布、push/merge/release 需按对应边界处理。
旧十小时、八小时计划及其付费额度已关闭，不能从历史“持续授权”推导新准入。
独立评审用于内容验收及契约要求的工程复核；评审只读，未见题由独立准备者保管。
记录暴露和分歧，不把 agent 评审冒充人工领域验收。

## 5. 跨会话接手与方向检查

每轮先核对 Git、当前维护入口、状态账本、运行身份及已提交/未结算任务；
历史 OPEN、旧交接、计时卡和聊天承诺不是当前授权或运行事实。
若同一卡点重复返工、规则持续增长或工程健康没有转成报告收益，
简短检查当前动作是否改善用户结果、是否有更简单路径、应如何停止无收益机制。
已完成的仓库改动按 AGENTS.md 提交，原始运行物保持不可变。

会话结束只记录有证据的成果、内容与工程状态、下一动作和阻断；
不把阶段切换或提交数当作质量完成，也不为记录过程新建逐轮维护文档。
下一轮未获外呼额度时继续离线代码/材料审计，不能自行启动付费测量。

## 6. 完成与资源边界

区分“工程验证通过”“候选在全新题上的内容改善”“固定样本稳定通过”与
“支持范围内多数场景能力获得广度验证”。旧失败不回写为通过，新失败不抹去已交付能力。
任何固定样本只能支持该样本的结论；多数场景目标还需预先冻结代表性广度测量。
新设计须先确定支持范围、抽样框架、类别/权重、独立保留样本、成功分母/阈值、
重复性、关键错误与成本上限，不能看报告后改门槛。保留题用于改进即转为已见，
最终24格继续封存，旧八场景前置不能自动恢复。
若当前资源不能再支持合格测量，报告已知效果、未解决缺陷与所需的具体范围决定；
不降低标准、隐藏失败、无限重试，也不以预算耗尽冒称完成。
