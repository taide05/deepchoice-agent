# 必要开发交付：执行与维修规则

更新：2026-09-29。交付范围、收尾判据和限制只见[现行地图](current-roadmap.md)，
实耗和已验证结果只见[执行状态](o1-execution-status.md)。本文件配合单场景最小展示验收，旧的全量优化推进规则不再适用。

## 1. 正常推进

一次推进一个用户可感知的成果：现有证据→定位→最小实现→相关验证→必要独立复核→
修复反馈→本地提交→更新结果。日常提交、测试和维修不逐项询问继续。
用问题与结果说明进展，不能用新增规则、测试数或代码量说明产品改善。

- 修改必须对应关键决策、决定性依据、行动安全或核心使用链路的已复现障碍。
- 来源事实、场景推断和部署就绪分别处理；保守输出仍须回答能回答的问题。
  不通过删除所有解释、增加unknown或替换为通用安全清单来制造质量通过。
- 不为次要措辞、引用计数、一般架构建议开新轮次；不扩展来源、平台或供应商。
- 原始产物留outputs，本地调试/交接留notes；更新维护入口，避免每轮新增永久计划。
- 报告已交付能力、未解决限制、下一验证点及预计工作范围。未知耗时说明原因，
  不提供虚构百分比，也不让已停止的外部运行保持“正在优化”的印象。

## 2. 维修与偏离

维修属于长程目标内的正常工作。按影响采取最小处理，不因跨文件或跨提交自动升级为新授权请求。

| 发现 | 行动 |
|---|---|
| 实现、测试或兼容回归 | 保存复现证据并修复；行为变化补相关测试，涉及生命周期等执行原独立复审契约 |
| 外部超时、限流或无结果 | 核对逻辑终态与底层HTTP，不把一次恢复后的429说成全程无故障；按有效运行卡收尾与对账 |
| 采集器/控制器缺陷 | 区分实现错误与规则过严。实现错误离线修复；规则改变先说明未来影响，不能回标历史结果 |
| 新证据推翻原假设 | 停止相关方案，调整同目标内的实现顺序；不能只换版本号继续相同尝试 |
| 不影响当前交付的问题 | 记录风险与后置理由，保留真实限制，不加入在做列表 |
| 安全、预算、身份、租约或未知异常 | 停止新准入、保全状态、完成能做的离线诊断；不降低安全或吞掉异常来继续 |

单场景内容验收原边界为一次针对性实质修复和一次同场景复核；用户随后另行允许离线心跳
维修，再明确追加一次原P01核对。调整后3次名额均已使用；当前仅对账、记录与本地提交收尾，
不进入第四次研究或新的内容调优。现行范围以地图为准；
更早同根因已有两种实质方案无收益时，不能借新目标重新开始同类修法。
给出失败依据、可行替代和必要范围取舍，不追加样本，也不把未修复的核心能力写成完成。
历史同类失败计入判断，换会话不归零。
可独立完成的工作继续；真正依赖外部条件/用户决定的部分保留明确阻断。

## 3. 持续授权与边界

- 用户要求的长程目标包含范围内实现、必要维修、验证、复核反馈、维护文档和本地提交。
  已有授权跨会话有效；正常步骤不重问，不引用助手自己写的审批措辞创造新门槛。
- 保留既有供应商/路由的数据传输边界，不打印或改写.env，不扩大数据集或供应商。模型分析的已授权人审边界以当前地图为准，不据此推导自动执行或生产操作权限。
- 用户已明确无需再逐次要求付费授权。必要的付费核对仍先冻结案例、最大增量、候选身份、
  用途和停止/恢复范围；遵守既有供应商与数据边界、累计硬上限及失败停止线。
  原12/48格计划和余额不构成执行计划，已停止根不能补跑。
- 不因阶段切换要求确认；只有实质范围取舍、新数据传输边界、破坏性操作或发布才需决定。
  等待期间继续不依赖该决定的工作。push/merge/release、外部个人文档修改保持单独授权。

## 4. 中断与恢复

依次核对Git与未提交文件→当前维护入口→已发生的外部副作用和准入账本→任务终态及服务
归属→产品/检查点数据库配对→兼容身份和预算，再继续安全工作。
不能因collector缺最终记录就重复提交，不启动历史实验服务、不直接改生命周期表或恢复备份。

- 助手额度中断：保全进度与完成提交，后续从断点继续；不为额度削减必需验证或消费reset credit。
- 主机蓝屏/高负载：真实研究与全套测试避免同时堆叠，遵循已有资源和停止线；不擅改系统或代理。
- 意外关机/存储异常：先确认已经发生的提交、任务和数据库状态；损坏时先备份并提出具体修复，
  不能把以往的修复命令当成通用脚本。恢复或破坏性操作遵循原授权契约。

不增加调度平台。使用现有durable生命周期、采集记录和本地交接；长程goal不等于后台定时自动化。

## 5. 验证与结束

- 行为变更先相关测试，生产代码/契约/测试冻结后完整验证；需要的故障、恢复和独立复审仍执行。
  仅文档变化复用有效全套，文档查差异、链接和事实即可。
- 本轮按地图的单场景目标先检查已有报告，再做必要的有界真实核对；旧 P04 失败如实保留。
  复用有效工程证据，不以离线通过冒称真实报告效果；没有配对便不宣称相对改善。
- 模型分析按已授权的人审契约单独表达，不把推断算作已验证事实，不硬编码案例答案或放宽来源核验。
  单场景验收不恢复 P04/P01/P08 三例全部通过的门槛；新输出前冻结请求与通过条件。
- 达到地图的新目标全部条件才宣布完成；额度耗尽或修复后仍不足时停止本轮尝试并报告未达成。
  更新 goal 状态遵循工具规则，不把范围退役、停止尝试或过去未达的目标追认为完成。

旧全面优化、配对回归和24/48格要求已退役为历史研究目标。冻结历史结果、工程契约和
安全边界继续有效；未来选择开展更广泛评估时另定范围，不让它阻塞本次有限开发交付。
