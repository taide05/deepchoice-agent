更新：2026-09-29。现行目标是完成单用户个人项目的可用版本，结束必要开发优化。
本文件替代原全面优化路线；旧S1/S2/S3及量化验收不再作为本次交付前置，

运行与评分事实只维护在[执行状态](o1-execution-status.md)，实施与维修规则见[执行规则](optimization-execution.md)。

## 1. 长程目标与范围

交付一个能从需求、候选出发，经默认durable流程生成可查看、可导出的技术选型报告的版本。
报告须解释关键约束、可追溯的决定性依据、条件选择及安全的验证下一步；证据不足时准确
说明缺什么，已有足够机制依据时不能只剩通用验证清单。工程能力与限制应能由代码、运行
说明和有限实测证据核对。本工作区交付开发事实，外部简历和面试材料另行处理。

本目标包含正常实现、必要故障维修、验证、独立复核反馈、文档和本地提交；不按PR逐个申请继续。
只处理阻碍关键决定、证据可靠性、行动安全或核心使用流程的已复现问题。
不纳入全案例打磨、满分/全verified、性能配对收益、并发认证和企业平台扩展。
2026-09-29用户明确选择保留条件选型目标，并允许有来源、列明假设、待人工审阅的模型
分析与概念方案。来源词法核验、模型推断和实际验证分别呈现；推断不能继承verified状态，
不能升级无条件胜者、需求满足或生产操作权限。此授权替代此前对此边界的待决定状态。
用户随后明确要求先完成原报告目标，验证包往后排。SQLite单场景验证包作为后续独立增量，
本轮不接入、不验收，也不加入下表完成前置；相关未完成草稿保存在本地忽略区。
保全主工作树六文件草稿；继续使用隔离候选工作树，禁止混入未验收草稿。

## 2. 完成标准

以下条件同时满足后，才能把长程目标标为完成：

| 交付项 | 可核对的完成条件 |
|---|---|
| 主流程 | 默认durable提交、进度、终态、报告查看/导出可用；适用时HITL可恢复；失败与受限状态可见。复用有效工程证据，只针对实际变化补验 |
| 有用结论 | 限定开发场景能回答决定性问题，给有依据的条件选择或真正必要的补充信息请求；不把未部署演练等同于无法讨论技术选择 |
| 依据与安全 | 决定性事实可追溯，场景推断和来源事实区分；无已确认的重大事实、安全或数据损失错误。未知如实可见，未经核验的操作不能变成生产执行建议 |
| 有限内容核对 | 最终候选的P04/P01/P08各一份开发报告，分别覆盖任务恢复、低运维数据需求、关键条件不足；独立GPT复核并记录分歧/限制。已有报告仅在产品身份及相关行为仍适用时复用，不能拼接成同批或稳定性证明 |
| 工程与交付 | 相关测试、冻结后的完整必要验证及契约要求的独立复审通过；启动/配置/使用说明准确、已知限制有记录，所有完成改动有本地提交 |

这是一项有限场景的开发交付验收，不声明全领域正确性、重复稳定性、统计改善或完整保留集通过。
P04/P01/P08固定用于检查能力，不能硬编码案例答案或因某例难做换成更容易的案例。
不设置新的分数竞争目标；但关键问题未回答、依据误用和重大错误不能靠“范围缩小”掩盖。
如果必要能力无法实现，交付未达标原因与可审阅的范围取舍，目标仍未完成；不能以“诊断结束”代替交付。

## 3. 推进顺序

| 成果 | 内容与退出点 | 当前状态 |
|---|---|---|
| A 核心内容修复 | 复用已存报告/快照定位证据到结论的丢失或过度降级，做最小通用修复；关键事实、适用性推断、部署就绪分别表达，保留安全门禁 | v14工程验收通过，但真实P04核心内容仍未通过；停止同类修法 |
| B 主流程和有限报告核对 | 检查真实使用链路；冻结修复候选并按前瞻边界补足必要报告，内容先审、用量后看；发现阻断按第4节维修 | v14仅P04完成且内容失败；P01/P08未提交，本轮已停止收尾 |
| C 版本收尾 | 修复必要复核反馈，完成最终工程验证、运行说明和残余限制记录，提交并按第2节验收 | B通过后；达到标准即结束优化 |

每次只维护一个在做成果，报告已完成什么、剩余哪些阻断及下一验证点。
开始实施后按代码证据给出剩余工作和时间范围；遇新阻断说明对预计结束点的影响。
不以测试数、代码量、PR数量或不断增长的问题列表代表完成比例，不承诺外部网络可控的精确结束时刻。

## 4. 故障维修与防循环

| 情况 | 处理与继续条件 |
|---|---|
| 代码缺陷、相关测试失败、已有能力回归 | 离线复现、最小修复、相关测试和所需复核；修复范围内自动继续，不另开产品方向 |
| 外部429、超时、来源不可达 | 按当前冻结规则停止/收尾并对账；区分已恢复的传输异常和产品失败。保留失败，不自动补跑。新运行如需不同停止规则，先给依据、影响与离线验证，不能事后放宽旧卡 |
| 控制器误判或采集缺陷 | 先确认是程序与契约不符还是契约设计不适用；前者最小修复，后者前瞻修订。只修阻碍本交付的缺口，不重建测量平台 |
| 租约、预算、安全、身份异常或主机中断 | 停止新准入，保全任务与数据库，核对已发生的副作用后修复；禁止重复创建不确定任务、绕过安全或改写停止根 |
| 新发现但不阻碍交付 | 记录影响与后置理由，移出在做列表，不自动扩大本轮 |
| 同一根因连续两种实质方案无收益 | 停止该修法，用现有证据判断替代方案或必要范围取舍；只改措辞、版本号或测试个数不算新方案，不靠采样碰运气 |

每个新增修改须指出受影响的用户问题、已有证据和可检验的预期。若新证据推翻方案，允许
调整实施顺序或放弃无效方案；保留用户改动和审计记录，不为维护旧计划继续错误方向。
范围/信任边界/发布等实质决定需要用户时，先完成独立可做的工作，再一次性提交具体决定。

## 5. 验证与授权边界

- 先离线消化已存证据；只有真实模型表现或真实使用路径无法由已有证据回答时，才准备付费核对。
- 新候选在采样前固定代码、案例、顺序、最大次数和故障处理；沿用已有durable采集能力。
  不自动要求两臂、两次重复、全开发集或保留集；不宣称因果改善便不为这种声明开展配对实验。
- 用户已明确无需再逐次要求付费授权。目标内必要的真实核对仍须先冻结候选、案例、
  最大增量与停止条件，遵守既有供应商/数据边界及累计硬上限156；余额不是待消费计划。
  v4及后续已停止的执行根都不补跑，实耗与最新停止线以执行状态为准。
- 旧冻结JSON、数据集、评分、停止根和账本保持原义；未来允许的重试/恢复必须事先有界，
  已停止协议不得重开。一般网络波动不能自动取消安全、身份、预算或租约门禁。
- 保留AGENTS与运行契约规定的行为变更测试、必要故障/并发测试和独立复审。最终代码/测试
  冻结后跑一次全套，纯文档或结果记录更新复用有效结果，不以反复全套代替真实内容判断。
- 不推送、合并、发布或修改外部个人材料，除非另有明确授权。原有私有配置不打印、不改写。

## 6. 文档效力

| 材料 | 当前处理 |
|---|---|
| 本地图、执行规则、状态、文档入口 | 保持现行；每种事实只维护一个入口 |
| 旧完整路线与S1/S2/S3、12/24/48格安排、配对收益阈值 | 执行要求退役，历史地图保留。未来若做广泛质量研究需另定范围；不能阻塞本次有限交付 |
| S0诊断、旧P01资格、过去实验的计划/复议文字 | 仅作对应身份的证据和问题线索；“下一步”“当前候选”“仍须”不自动生成当前任务 |
| 冻结机器协议、原始报告、评分/哈希/账本 | 历史证据不作废、不重标、不删除；停止卡不提供新授权 |
| 生命周期、预算、引用、安全、兼容契约及工程验收 | 继续有效；沿其适用身份复用证据，不能因路线缩小绕过正确性要求 |

文档效力调整本身不表示产品已改善。详细协议的适用边界见[评估说明](product-effectiveness-optimization.md)。

## 7. 当前下一成果

v14的来源准入提示已通过工程验证，但唯一真实P04报告仍未达到本路线第2节的内容标准。
主评与独立复核都发现重启丢失、组件责任、硬约束下的条件选择和概念过渡方案未解决，
且存在与硬约束冲突的BackgroundTasks分支及未获来源支持的数据库重放引用。
合成有两条绑定分析，但都依赖引用状态unknown的来源，最终没有人审分析；放宽该来源门禁
会暴露未经证实的方案，不作为修复。具体证据与运行账本见执行状态。
停止此类准入标签、来源展示和提示措辞修法；P01/P08不因本次余额自动提交。
恢复工作时应先确定能产生有据条件方案的实质设计，或由用户明确接受更小的内容交付范围；
不能把当前报告判为通过，也不能把隔离演练计划当成选型与迁移设计。
长程目标尚未完成，验证包继续后置。
