## 本轮交付定位

DeepChoice 是单用户、可信网络内使用的**技术选型 Agent**。用户输入需求与候选后，默认
`/api/v1/tasks/*` 流程检索、比较并生成可查看和可导出的选型报告；证据充分时可给条件建议，
不足时显示来源核验结果、缺口或受限状态。报告中的模型推断与概念方案单独标为
“待人工审阅”，表示这部分尚无语义与场景适用性验证；这不是额外的人工作业或审批步骤。
来源词法核验也不证明部署成功。对重要决定，使用者仍需核对决定性依据和假设；
报告本身不授权迁移或生产操作。

本轮保留已有的来源、预算、HITL、安全和生命周期边界，不增加认证、分布式执行、
额外验证包或新的付费案例。P04/P01/P08 的内容改进转为未来独立工作；不因旧计划或
剩余研究额度自动启动。外部简历和面试材料不在本仓库内修改。

与安全验证步骤。重要选型仍应核对决定性来源和适用条件。

## 已确认的产品限制

- 最新可归因的真实内容核对是 2026-09-29 synthesis v14 的单次 P04：主评与独立复核
  均判失败。报告未充分解释重启丢失、至少一次语义、组件与业务幂等责任，未给出符合
  “不能静默丢失”约束的可用条件选择及概念过渡方案。v11 离线修复只撤回未经核验的
  分支条件，不补足这些内容；P01/P08 没有当前候选报告。
- 来源不可达、片段不足、跨语言不确定或关键输入缺失时，结果可以是 `unknown`、受限报告
  或请求补充信息。不能把这些状态解释成已验证的技术结论；无报告的失败任务也须可见。
- SQLite runtime 仅单实例/单 worker；产品库与 LangGraph checkpoint 库须成对维护。
  API 没有用户认证或任务所有权校验，只限单用户可信网络，不能直接暴露公网。
- 历史 300-case 指标、12-case smoke 和较早的真实小批次各有不同身份、日期与分母，
  均不能证明当前 v11 的广泛报告质量、稳定性或相对改善。

## 后续工作边界

本轮交付后停止同类提示、引用展示和测试数量打磨，不补跑已停止的执行根。
若将来要让报告承担“可用条件选型”承诺，先定义能够覆盖关键问题的来源与结论生成方案，
再为新候选做有界真实核对；P04/P01/P08 既有失败与未完成记录仍是问题线索，不能冒充通过。
SQLite 单场景验证包继续后置，须作为独立增量评估。
范围内若发现实际安全、数据损失或核心链路回归，按[执行规则](optimization-execution.md)
诊断并修复；仅可能改善措辞或分数的问题不重新开启本轮开发。
