## 本轮交付定位

DeepChoice 是单用户、可信网络内使用的**技术选型 Agent**。用户输入需求与候选后，默认
`/api/v1/tasks/*` 流程检索、比较并生成可查看和可导出的选型报告；证据充分时可给条件建议，
不足时显示来源核验结果、缺口或受限状态。报告中的模型推断与概念方案单独标为
“待人工审阅”，表示这部分尚无语义与场景适用性验证；这不是额外的人工作业或审批步骤。
来源词法核验也不证明部署成功。对重要决定，使用者仍需核对决定性依据和假设；
报告本身不授权迁移或生产操作。

本轮保留已有的来源、预算、HITL、安全和生命周期边界。SQLite 验证包、认证、分布式执行、
完整面试材料包及外部简历修改继续后置；旧计划和剩余额度不产生新的执行任务。

## 新目标与执行顺序

**目标：至少一个真实场景的报告能回答“建议选什么、为什么、什么条件下改变选择”，
并能通过默认流程查看和导出，形成可诚实展示与讲解的有限产品证据。**

1. 先核对已有报告的原始请求、生成身份、来源、关键约束与当前候选差异。
   与最终候选兼容且证据充分的结果可以复用；旧身份的报告只可作为标明版本的历史示例，
   不冒充当前候选结果，也不因可读或任务 completed 就判内容通过。
2. 依据真实需求和来源可得性锁定一个适合现有能力的场景，优先既有案例。
   在新输出产生前固定请求、硬约束和通过条件；不通过删改硬约束或失败后换题制造成功。
3. 已有证据不足时，最多开展一次该场景的真实初验。研究前冻结候选身份、输出目录、
   单次上限与停止条件，使用默认 durable 路径和既有供应商。原始报告与研究账本留本地。
4. 初验不足时，只有明确可复现缺口与实质修复方案才进入一次针对性修复；
   履行相关验证后，最多对同一场景再复核一次。不能用提示措辞反复微调或相同代码重采样
   代替修复；历史同根因失败计入是否已有可行方案的判断。
5. 对拟展示的最终报告做一次独立内容复核，留下简短结论；在已有文档中补齐启动、
   演示操作和已知限制，完成本地提交。本阶段记录经验证的项目事实，不改外部求职材料。

## 完成条件与停止条件

全部满足后才能宣布新目标完成：

- 最终候选绑定的一个真实报告给出明确的有条件建议，回答该请求的关键问题；
  不能只有通用安全清单、待测事项或来源摘录。
- 决定性依据可追溯，推断与事实可区分，不违背用户硬约束，不把未验证的假设当保证；
  来源 verified 不作为语义正确或场景适用的证明。
- 默认链路支持提交、状态可见、适用时的 HITL、报告查看与导出，失败也可见。
  未改动部分复用有效工程证据；新增运行记录实际使用链路，不能声称覆盖未走到的分支。
- 独立内容复核通过；必要代码验证通过；启动/演示说明、限制与可追溯提交齐全。

新增真实研究累计最多 **2 次**（初验 1 次、实质修复后复核最多 1 次）；
已经提交但失败的研究也占名额。每轮最多使用一次现有有界前置检查，
运行前写明外部调用上限；前置失败先诊断，不自动扩大调用或重跑。
所有调用遵守既有总预算与数据边界，新研究必须使用新输出目录，旧停止根保持关闭。
服务波动、控制器误判或不确定提交先按执行规则诊断、对账，不将异常变成额外采样额度。

没有可行修复方案、一次修复后仍不足，或触及额度/安全/数据边界时，结束本轮尝试，
记录目标未达成、具体缺口和现有工程演示边界；不追加案例、重复抽样或放宽通过条件。
扩大范围需要新的范围决定。停止尝试不等于验收通过，也不能据此把目标标为完成。

## 局部结构修复：synthesis v15

2026-09-29 用户先增加离线评估，随后允许局部结构修复。实现针对 JSON 格式检查与
来源绑定契约之间的缺口；只读方案复核支持此方案，代码独立复核及验证结果见执行状态。
合成违规的可复现依据与离线复现边界见[执行状态](o1-execution-status.md)。

**合成节点已增加本地绑定结构检查，只有结构违规才最多纠正一次。**

- 归一化前复用现有来源事实和模型分析绑定器，检查列表上限、实际绑定损失与引用有效性。
  合法空列表、正常弃权、答案不够好、来源尚未 verified 均不触发纠正。
  首因超限导致的后续引用失效合并处理，不按每条分析重复请求。
- 纠正使用相同原始请求、硬约束、来源和候选；反馈限于固定错误码、计数及运行时计算的
  合法编号，不回传或持久化模型原始正文。模型重新生成完整回答，随后重新经过全部绑定、
  原需求约束和引用校验；不截断超限列表、不合并两次回答，也不提高四条来源上限。
- 仍调用现有 `call_model`，复用冻结参数、usage、预算和 Trace。每次节点执行最多两次逻辑
  生成；现有每次调用最多三次传输尝试，因此本节点最多六次物理请求，增量最多三次。
  同一 run 的节点恢复/重试仍受已冻结的总调用、token 与活动时长限制，不能将六次误称为
  跨恢复的 run 级上限。预算、租约失效和取消必须传播，不能转成结构纠正或成功回退。
- 第二次仍违规或普通服务错误时，保留第一份回答经原有绑定器处理后的保守结果，并记录
  固定结构失败类别；不再纠正。引用 unknown 仍撤回相关分析，结构合规不授予事实或操作权限。
- 纠正协议、反馈模板与次数上限纳入冻结运行资产，旧身份可读但不能在新行为下同 run 续跑。
  结构诊断与 JSON 解析诊断分开；现有 `repair_attempts` 只表示本地解析次数，不能冒充模型纠正次数。

实际修改四处生产模块：合成节点、绑定检查/诊断、既有响应 shape 复用及 manifest 资产；
无数据库迁移、前端或网络路由改造。验证覆盖触发/不触发、至多一次纠正、二次失败、
预算/Trace/取消/租约、版本兼容及引用门禁，并执行冻结后的完整验证与独立复核。
纠正反馈与绑定器共用原始需求编号规则，排除分析器派生问题；不回显模型正文。

运行时固定挑选四项来源需要另定选择规则，可能遗漏原问题的关键依据，暂不采用；供应商
严格 JSON Schema 能力未经本次离线评估确认，不作为方案依赖。引用超时尚无确定实现缺陷
证据，不放宽安全抓取或延长超时。结构修复只能减少格式违规造成的丢弃，不能保证模型输出
合规、来源可达或 P01 内容通过。最后一次复核因运行中断未到合成节点，无法验证真实效果；本轮名额已用完。

  “不能静默丢失”约束的可用条件选择及概念过渡方案。v11 离线修复只撤回未经核验的
