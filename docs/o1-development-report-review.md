## P01：SQLite / PostgreSQL

| ID / 出现位置 | 关键声明或风险 | 助手核验结论与原报告支持边界 |
|---|---|---|
| P01-01 / 两份 Winner、推荐、排序、场景适配 | SQLite 更适合个人低写入、低运维应用 | **条件性合理**；[官方用途](https://www.sqlite.org/whentouse.html)允许此方案，但需要真实写入竞争/部署形态，不由日活直接证明。原报告多引用内部博客，不等于官方背书 |
| P01-02 / 两份推荐、权衡 | SQLite 嵌入式，无独立数据库服务、没有数据库网络往返 | **支持架构属性**；不代表整个 Web 产品零维护、没有任何认证开销。r1 将“零维护”写成绝对属性过强 |
| P01-03 / 两份推荐、权衡、场景适配 | WAL 同时一个写者、多个读者 | **支持**；[WAL 文档](https://www.sqlite.org/wal.html)明确单写者，但未量测本项目锁等待/写事务长度。r1 部分引用为无效占位 `\N`，不能视为有效引用 |
| P01-04 / r1 单客户端性能、r2 多处等效查询性能 | SQLite 性能优于 PostgreSQL | **适用条件不足**；无同版本/持久性设置/查询/硬件对照，网络开销属性不能直接推出任意等效查询更快 |
| P01-backup / 两份推荐、排序、场景适配 | 备份只需复制数据库文件，简单可靠 | **高风险缺条件**；[在线备份 API](https://www.sqlite.org/backup.html)需要一致快照/锁条件，WAL 文件属于持久状态。不能教用户在运行中只复制主 DB 文件；应区分停写/干净 checkpoint 与在线快照。不是宣称离线单文件复制永远错误 |
| P01-06 / 两份全文检索 | SQLite FTS5 支持基本全文检索 | **功能支持**；[FTS5](https://www.sqlite.org/fts5.html)可核对，但报告的首页占位片段不提供此声明的原始段落；中文分词/相关性等本项目需求仍未知 |
| P01-07 / 两份权衡 | PostgreSQL 有 tsvector | **可核对功能，不决定本场景胜负**；原报告只给文档首页，未给相应段落或中文检索条件 |
| P01-08 / r1 confidence、推荐、场景适配 | WAL-reset bug；3.51.3+ 修复 | **已确认，不是编造**；WAL 官方 §11 同时列出特定竞态和旧分支 backport。报告应说明不是所有并发写入都会触发，并保留 backport 选项 |
| P01-09 / 两份 PostgreSQL 排名、权衡 | PostgreSQL 更丰富的扩展、复制/规模化能力及新增运维成本 | **方向合理但部分支持**；[并发文档](https://www.postgresql.org/docs/18/mvcc.html)支持并发机制，不自动证明这个应用用它就是过度设计。r2 的“更强 ACID”没有明确比较条件；SQLite 自身支持事务 |
| P01-10 / 两份迁移建议 | 写并发增长后平滑迁移；r2 ntfy 示例证明路径成熟 | **部分支持**；案例不是本项目迁移保证。缺写锁等待/失败率/事务长度的观察门槛、数据校验和切换回滚；不能要求先跑到失败才迁移 |
| P01-11 / 两份争议区全部条目 | 用分数差、authority、citation/benchmark 类型裁决 A_correct | **不构成事实裁决证明**；A/B 经常只是文章标题，未展示相反原子主张。内部博客被判更权威不能证明性能结论正确；r2 还有两条同源技术比较不是本题的争议 |
| P01-12 / 两份 What/Why/参考来源 | Redis/Neo4j/MySQL、React、自托管清单等是本决策强证据 | **相关性不足**；未解释这些资料如何支撑当前数据库决定。泛官方首页只返回 “Official documentation site for …”，不是检索到完整功能页 |

可执行修正方向（本轮不实施）：明确当前单写/部署假设；提供安全备份步骤；迁移条件绑定写等待与失败观测；用具体主张/段落替代分数裁决与首页占位引用。

## 优先优化假设（不是本轮实现或改善结论）

1. **相关性/来源分层先于更多 Prompt 调参。** public snapshot 可见内部条目含 Expected winner/Known Contradictions 模板，无关条目被高分提升；源码 `classify_source_type(source='chroma')` 把所有 Chroma 来源当官方，证据链又把文章标题直接当 conclusion。这能解释观察到的伪强证据，但仍需 O2 离线回归复现以验证修正效果。不能据此证明某个模型天生不适用。
2. **真实正文先于 URL 首页占位。** P01/P06 official 结果只返回首页占位说明，P07 空结果；先获取题目对应段落，保证来源与关键声明绑定，不能靠名为 Official 就给高分。
