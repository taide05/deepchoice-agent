## 3. 内容评估口径：key-claim-occurrence-v1

保留必答与冲突 0/1/2：错误/遗漏 = 0，部分正确但缺条件 = 1，正确且说明条件 = 2。
决策得分分母 = 2 × 冻结必答问题数；冲突得分分母 = 2 × 冻结冲突点数。
无冻结冲突点记 N/A，并检查捏造冲突。重大事实错误另列，不能用“赢家合理”抵消。

关键声明包括直接支撑推荐、否决候选、关键数字和风险边界的事实及适用性推论：

1. 按报告顺序记录行号与 atom。功能事实、数字、条件、项目适用性分别拆开。
   摘要、排名、权衡、场景适配重复出现逐次计数，不能语义去重。
   同一 atom 的多个引用合成原始引用集合，不把引用数当声明数。
2. 支持状态为 supported / partial / unsupported / unknown / uncited。
   完整引用支持率 = supported ÷ 全部关键声明；其余均在分母，并单列各类数量。
   部分支持不折算半分；打不开、片段不足、同名绑定不清或跨语言不确定保持 unknown，不判事实错误。
3. 来源质量逐项为 eligible / ineligible / unknown。
   eligible 须有原始直接权威/一手依据且版本、日期与场景适用；质量率 = eligible ÷ 同一全部声明分母。
   官方身份只能证明相应功能，不自动证明比较优势。性能必须匹配版本、硬件、负载、缓存和比较对象。
   未保存这些条件不能靠当前网页补齐。unknown 在分母且单列，比例是已确认覆盖率而非“未知全错”。
4. 引用支持与事实核验分开：低质量来源可能表达错误命题，文字支持不等于事实正确。
   新查的正确资料仅作事实核验，不能给原引用补分；原检索官网入口占位片段不能充当细节正文。
   无效行内标签不由 Sources 总表自动修复；同名标签不强行选最有利来源。
5. 来源目录/标题、内部强度与分数、裁决元数据、Winner/置信度字段、场景复述、纯未来操作指令、
   参考总表和系统引用投影不独立计为技术声明。操作句内嵌的配置/兼容/哈希等风险仍拆项计数，
   不因使用祈使句而排除。标题数字被推荐正文采用时才逐处入账。
   元数据是否虚构证据/冲突由必答、冲突 rubric 与重大错误检查另审，不从质量审查消失。

逐项保留原引用、判断依据与问题 ID；coverage 表注明纳入/排除范围。
台账完整是声明分母完整，不是每个网页都已核实：无法判断可保留，但不能删除来提高比例。
系统 verified/unsupported/unreachable/unknown 仅为确定性词法/可达性投影，与助手语义核验并列，不互相代替。

质量只对产出报告评分，同时报告覆盖率 = 可查询报告 ÷ 已启动 run。
失败报告不伪填质量零分，也不从完成率分母消失。
质量用于门禁的均值采用逐报告 macro；另列引用/来源整体 micro 分子分母。
开发与保留集分开，不合成一个总分；无完整原子台账或无配对报告时质量门禁 unavailable，不通过。

## 4. 评审与复核资格

本轮用户允许助手做已有开发报告主核验：assistant_review、非盲评、未人类校准。
独立助手复核不冒充第二位人类；必须写明复核对象/覆盖程度/未解决分歧，不自动把六份全部认证。
重大错误、争议引用和所有声称改善的项需第二位评审留下依据；缺复核保留暂定，重大错误数不能强填 0。

未来锁定候选的配对报告隐藏版本/profile 标签并随机顺序评审，评分锁定后再看 Trace 归因。
主评与独立复核者记录模式、盲评、参考日期、分歧及处理；人类校准另记，不以助手一致代替。
当前无付费 judge 或默认路径新裁判。人类校准未执行时助手结果可用于诊断，
但只能给“助手评审下的暂定门禁”，不能声称人工质量验收或经校准最终产品通过。

## 5. 运行与成本协议

正式测量前锁定干净 Git、Python/依赖、DeepSeek Flash 实际模型、thinking/输出上限、
Prompt/registry、workflow/state/citation/HITL、知识资产与非敏感配置 hash；逐 run 保留 immutable manifest。
旧 manifest 不兼容时创建新 run，不强行恢复；不复制密钥/原始私有端点。
当前补证总 deadline 为 630 秒，旧 20 秒身份不能同 run 续测；标准硬预算不提高。

在明确授权的检查额度内先检索健康检查，再最小 LLM JSON/tool/thinking 探测；
检索 health-check 不证明 LLM 连通。2026-09-17 单例前置两者分别检查通过，历史 degraded
仍保留；前置通过不证明实时限流消失或批次资格。
使用单实例/单 worker durable /api/v1/tasks/* 与 API 采集器；不使用历史 direct-graph 工具。

serial 必须整 case 并发度 1，concurrent 必须 12 条完整任务同时在途；
HTTP 提交并发不是研究并发。记录顺序/随机种子、提交断点、run 身份与观察截止；
轮询 running 峰值是下界。中断先核对已创建任务，不因缺最终行重复创建。

缓存默认开启；每个 profile/repetition 使用同一知识快照与独立空实验产品/检查点数据库对，
同一自学习设置，前后配对只改变声明变量。不清空用户数据库，不把预热实验充当冷启；
预热/模型下载/启动时间与提交后的研究时间分别记录。
P08 按冻结动作补一次有界上下文，再暂停则 limited_report；其他案例默认 limited_report。
人工等待单列，不因缺用户约束就宣称应触发现有 evidence-insufficient gate。

所有已启动 run 按普通报告/受限报告/失败/超时/取消/未结束互斥分类，数量合计等于分母；
另列 HITL/无需人工介入数、wall/queue/active/人工等待、makespan 与失败类别。
Trace 与预算 ledger 分列；token 记录已知小计及完整性，缺 usage 为 unknown，不回填历史。
缓存 hit/miss 仅在每个调用的分项完整且输入 > 0 时计算比率；0 个已知调用不是零命中。
节点/attempt 热点不能直接证明 cache miss；unpriced-v1 金额 unavailable，不能宣称金额节省。

每 run 保持 60,000 total tokens、96 LLM、72 retrieval、900 秒 active，80% 软提示。
不自动补跑、扩大预算或放宽 gate。首个来源降级/限流、预算/租约/恢复异常或主机异常停止后续准入，
保留已提交 run 的结果/成本，依正式取消流程收尾；不能抹掉失败或取消已提交 reservation 的计费。
六源来源降级以 source envelope 与 provider telemetry 判定。动态引用安全抓取在精确
`safe_fetch_public` / `safe_fetch` / GET 上产生的已知 `UnsafeUrlError` 安全类别，沿产品契约记为
`unknown/network_uncertain`，本身不构成六源降级；未知类别、普通 transport failure、错误上下文和
5xx 仍触发实验停线。无可靠截止/usage 或采集身份失配时标无效/unknown，说明原因；替代运行另计新授权。

## 6. 门禁与结项

串并发需同 dataset/env/model/asset/knowledge/HITL、同 case/repetition/兼容 manifest 配对；
每次重复有全部 12 份成对可评分报告，否则质量 unavailable。不跨修复版本或失败批次拼表。

原并发阈值不变：

- 并发完成数不低于串行，逐例不新增重大事实错误。
- 决策/引用支持/来源质量 macro 均值下降各不超过 5 个百分点；冲突不超过 10 个百分点。
- 任一 case 决策下降不超过 20 个百分点；下降超过 10 个百分点的 case 最多 2 个。
- 同时展示失败/限流/重试/unknown usage/token/调用/耗时/makespan；usage 不完整不能宣称一致或节省。
- 两次重复均通过才是并发门禁通过；仅第一轮/六份开发报告/离线测试通过不能替代。

比较器 scores.csv 仅统计已录入数值，不能验证声明分母、复核或校准资格；
最终报告必须附台账/评审资格并先检查可评性，不把其 passed 布尔值单独当最终验收。

| 状态 | 必须具备的证据 | 后续 |
|---|---|---|
| O1 进行中 / unavailable | 缺授权、冷启资格、成对报告、评分或复核；当前即此状态 | 继续对应 O1 任务，不进入 O2 |
| 诊断阶段停止 / failed | 已完成相应测量且有确定失败与归因；保存全体已启动分母 | 修复/重测另授权；不是 48-run 基线完成 |
| O1 评估闭环 | 冻结版本身份，完成授权的测量及可评分内容，复核主要错误/争议，汇总成本/失败/残余风险并冻结一个优先假设 | 可结论“不通过”，不能包装改善；缩减原 48-run 交付须用户明确接受 |
| 并发门禁通过 | 同锁定候选完整 48 新 run 的两次重复均满足阈值及复核；注明助手/人类校准资格 | 与 O1 闭环分别报告，不自动启动 O2 |
| 最终产品质量验收 | 盲评保留集、独立复核及明确的人类校准/验收记录 | 缺记录不得声称已完成 |

## 7. 优化候选与 O2 边界

O1 问题归为需求理解、检索覆盖、来源适用性、冲突处理、结论推导、引用/表达、运行环境。
按是否改变决策 × 影响案例数排序后估修复成本，只冻结一个主要变量，写目标案例/机制/回退条件。
当前错误分析是诊断，不是已证明的质量、缓存命中或并发改善。

O2 另按用户授权实施；改代码前锁定目标阈值。原默认优化要求保留：
质量项需目标案例两次均改善、其他开发逐例均分不下降，无新增重大错误，引用/完成率不下降；
效率项先对每 case 同 profile 的两次成本求均值，再计算前后逐 case 配对节省比例，
最后取 case 比例中位数至少 15%，且正确性/引用/完成率不下降，
usage 不完整不能声明 token 节省。替代门槛须事先明确，不事后调低。
前后测同 7 天窗口/知识资产/配置，仅声明变量不同；漂移需重确认配对，结果不一致记尚未证实。
候选锁定后的保留集任一重大错误或质量退化不通过；继续调参则该集退役为开发集。
这些是小样本决策门槛，不是统计显著性或总体质量保证。
