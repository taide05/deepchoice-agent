# 选型报告与效果评估

更新：2026-10-24。本页保留实用评估方法，不再规定固定晋级程序。后续交付标准、样本规模、
阈值和评审投入由用户与 dsh 决定。旧 §6.7/§6.8 的数值用于解释旧实验，不再自动阻止新开发。

## 报告首先应帮助用户做选择

看三个问题：是否回答真正影响选择的需求；理由是否有适用依据；限制是否清楚。
可以给明确推荐、条件性偏好，或说明哪些缺口会改变选择。不要强求唯一赢家、固定五大专题、
每句话都有引用、每个小项都有版本号，或在用户未要求时展开完整部署审计。

- 核心项取自原请求中真正改变选择的内容；数量按题目需要，不预设必须五项或恰好三项。
- 补充细节不完整可以记录，不自动否决整份报告。硬约束及会改变选择的错误仍需处理。
- 来源事实与推论区分；推论可由已知事实和用户条件得出，不要求文档直接写出“该用户应选择A”。
- 事实的版本、日期、许可、地域等在影响结论时核对。官方来源不是固定数量门槛，营销页也不因官方域名自动成为充分证据。
- 有用的条件建议可以算相应范围内可用；只有通用缺口列表或空泛暂缓不算完成选择任务。
- unknown 表示尚未确认，不表示没有该能力。自动引用检查与语义评审各有用途，不能互相冒充。
- 内容评审以用户实际看到的报告为主，必要时追溯保存材料；内部存在答案但报告没有呈现，仍是产品问题。

## 不再把报告评成全面部署审计

评审先判断用户是否获得有用、依据合理的核心取舍。通常只需读报告与关键来源，
不用为每个背景句建立断言账本，也不要求先把所有文档、版本和旁支核验完。

| 情况 | 判断方式 |
|---|---|
| 核心选择有据，补充配置/运维细节不足 | 可以可用；列出需要另查的细节 |
| 有明确条件偏好，部分条件待确认 | 可作条件建议；判断条件是否具体、是否掩盖决定性缺口 |
| 来源引用 unknown，但保存正文支持相关分析 | 核对正文和适用性；不因自动状态单独否决 |
| 没命中预列参考 URL，但其他材料覆盖同一事实 | 按实际支持判断，不按 URL 字符串扣成缺失 |
| 只有缺口清单或关键比较一侧空白 | 记录核心未回答，不能靠诚实暂缓算作完成 |
| 存在影响选择的错误或错误前提 | 指出具体影响；必要时判该建议不可用，而非因小错误否决所有内容 |

开发时 dsh 可自己读报告、抽查关键事实并比较前后，独立评审按争议与需要安排。
对外指标的评审覆盖必须写清：全评、抽评或助手评审各按实际称呼，不要求一律专家双盲全审。
旧 11/12、12/12 全部必答、0 错误等组合门槛退出默认流程；以后采用的数值由用户与 dsh
按项目用途确定，不由历史文档自动决定。旧失败结果仍按当时规则保留。

## 开发和正式测量分开使用

开发可以用已暴露题、固定证据、节点调用、重复运行及小批量比较。目的是尽快判断修改是否有效，
不要求每次重新准备未见题、独立封存或双评。模型/提示/规则可以调整，记录关键版本及结果。

准备对外发布的指标时，说明样本来源、开发暴露情况、版本、评审方式和失败分母。若声称未见集
结果，评测答案不用于该版本调参；开发集成绩可发布为开发成绩，不改称泛化成绩。
正式批次如改实现或评分，另列版本，避免混算或只保留成功结果。

先做能回答当前决策的问题即可：改动是否改善核心回答、错误是否减少、时间/token是否合算。
不必先把所有评测工具建完才开始修产品。基线、参考核验和展示可按资源安排。

## 指标用最少的清晰定义

| 项目 | 记录方式 |
|---|---|
| 运行完成 | 已提交执行中获得报告的比例；超时、失败及受限报告分别列出 |
| 内容可用 | 在声明的样本范围内，报告是否回答核心问题；注明条件简报与完整推荐的区别 |
| 核心覆盖 | 已回答、部分回答、缺失，保留分母；不用报告长度代替 |
| 事实支持 | 分开统计“报告实际提出的论断受到支持”与“回答需要的事实已取得” |
| 重要错误 | 列具体错误及影响，不因小格式问题判整份不可用 |
| 效率 | 实际墙钟/active时间、请求、token；费用不明时写unknown |
| 基线 | 相同case、模型/预算及可比证据条件；披露两臂差异，失败也保留 |
| 评审 | 写明覆盖数与助手/人工身份；抽评就称抽评，不推成全量复核 |

已有工具使用 N/S/R/E 等字段时保留其既有定义与报告绑定，不另造一套数字。比较共享证据时，
共享采集只计一次实际花费，两臂增量分别归属。原始报告及评分按 case/run/版本对应保存。

## 历史数值的效力

旧计划包括12题开发/校准、120题正式配对、11/12开发晋级、可用率80%、事实支持90%等目标。
这些是过去的计划选择，不是行业标准，也不是接手者必须先完成才能继续工作的永久约束。
原投递目标未被本次文档修改宣布完成；用户与 dsh 可以保留、调整或重新组织未来目标，
但不回写旧结果为通过。
