# 选型质量评估协议

更新：2026-10-19。本页是开发验收与正式代表性评测的唯一指标定义入口；规划不等于工具已实现或外呼已授权。目标见[路线](current-roadmap.md)，实际准入与候选见[状态](o1-execution-status.md)。旧 quality-selection-v1、旧四例晋级、额度追加及已退役的八场景前置设计完整保存在[历史快照](archive/quality-direction-20261005/evaluation-protocol-snapshot.md)和[Q0 原件](archive/quality-direction-20261005/quality-selection-q0-snapshot.md)，只解释当时实验，不授权当前研究。

本页定义交付/测量标准，不能替代[路线第1节](current-roadmap.md)的完整链路能力目标。
2026-10-09执行方向调整不改变已有冻结数据、评分、失败结果或最终24封存；每次测量的
诊断/成果证明目的由执行规则与当前状态明确，不因完成局部修复自动运行预设四例。

## 当前内容验收边界

旧八小时计划及其三类请求加一次重复的四报告批次已经结束，0/4 结果和全部
原始材料保持历史原状。下一轮**舍弃所有 Codex 时期使用过的例子/题**：
不把旧问题、改写题、同技术组合与约束的变体用作开发预设、内容验收、
保留集或成功分母。旧材料只为解释历史失败和核对机制，不作为新题调参输入。
下一轮题目由独立准备者产生并与旧题查重；实现者冻结候选后才接触未见题。
开发修复阶段每个修复包完成后先用一份全新题报告检查效果。题目、必答项、来源政策、候选身份、
额度和停止线应在单例运行前冻结，且不得根据输出换题或改 rubric。未获新额度时只可
离线准备协议及获委托的材料。语义内容判定沿用第 2 节；单例通过是进入小规模校准的
阶段门槛。最终交付需要代表性样本、可信指标和基线比较，不能自动恢复旧四例、八场景或最终 24。

## 1. 新题集与运行身份

连续单例题应逐步覆盖不同技术取舍、硬约束、需求缺项、来源版本与适用范围。
独立准备者先查重 Codex 期间所有已用题及近义改写，保存查重结论，
再冻结原始请求、影响选择的必答项、可接受的条件判断、严重性锚点、
数据集 ID/hash、来源政策与暴露状态。任何用于开发反馈的题立即失去未见资格。
同条件比较须冻结基线与候选 commit、资产/manifest、模型参数、依赖、
检索/缓存策略、HITL、采集器、环境与各自额度；失败照计。
下一轮题数和研究成本由新授权决定，旧数据集不能自动成为基线或验收集。

### 1.1 代表性与数据隔离

- 规划百例以上的独立需求；精确样本数由支持范围、类别覆盖、期望测量精度和预算共同确定。
  不用同一题的措辞改写堆数量；同主题/同技术组合的相关需求按组划分，避免跨集合泄漏。
- 在看输出前定义领域、任务类型、难度及类别权重。覆盖候选对比与开放选型、不同硬约束、
  来源冲突/不足、版本条件和需要澄清的需求；报告每类数量。自建分层集须说明抽样方法，
  不能把人为类别占比当成真实用户分布。代表性首先相对于声明的支持范围成立。
- 分开开发材料、小规模校准集与最终未见评测集。用于修复或评审校准的题不进入最终分母；
  不预先用未见题或参考答案制作提示示例、知识库、学习文档或检索缓存种子。正式运行只输入
  协议允许的原请求及澄清，参考答案不投喂系统。既有已见题仍只作历史诊断。
- 每例冻结原请求、约束、必答项、允许的条件性结论、参考依据及日期/版本、可答性、暴露状态。
  参考依据供评审使用，不投喂系统；不强求唯一推荐，不以命中产品名代替回答正确。
- 独立准备与查重后冻结数据集 ID、版本、hash、日期、分组与切分清单。候选锁定前实施者
  只接触类别及协议；正式执行期间不据反馈改代码、提示、参考答案或评分规则。
  如需修改，关闭当前版本并保留结果，已暴露题转开发材料；后续正式结论使用新的未见集。

## 2. 报告内容判定

每例只评原始选型需求；普通问题不能因提到迁移而被扩展成完整部署/回退验收。每份报告记录下列检查、理由和不可评项；五项均通过且无关键错误才记为“可用且有据”。结构字段、引用计数、自评分和正文长度均不能替代正文判断。

| 检查 | 通过条件 |
|---|---|
| 约束与回答 | 不违背硬约束；回答影响选择的必答项，或具体说明缺口及其决策影响 |
| 有用建议 | 有理由的选择或条件分支、关键取舍与可观察的改变条件；不能只给通用清单 |
| 决定性依据 | 改变选择、排除候选或界定风险的事实有保存的适用来源；推论列出前提且不过界 |
| 不确定性 | 明确未知与场景假设；说明能答与不能答之处，既不夸大也不无差别弃权 |
| 一致与安全 | 摘要、分析、结论一致；不捏造能力、实测阈值或来源，不保证危险操作安全 |

**关键错误**包括违反硬约束，捏造决定性能力、来源或测量，反转关键因果/适用条件，缺依据却关键排除或保证，以及可能丢失数据或破坏安全的操作。即使建议碰巧合理也记录。**重要缺口**使用户无法理解当前选择或下一验证点，对应项不通过；**一般问题**如格式、重复和非决定性旁支引用不单独否决报告。不能因字词出现就机械定错，须说明是否影响本案选择。

对每条决定性判断，保存报告定位、原引用、来源保存位置及版本、适用前提、支持/部分支持/不支持/未知和严重性。事实、来源支持与推论分别核查；新查资料不能回填原报告的引用。记录原问题实际回答、检索与合成的来源事实、绑定/核验/渲染前后信息损失，及 token、调用、耗时。来源不可达或跨语言不确定保持 `unknown`，不能据此认定主张虚假。

## 3. 开发判断与独立复核

局部回放只证明该局部行为。开发修复阶段每包一份原始报告可判断该题是否可用及本轮暴露的问题；
跨问题收益仍须由后续预冻结的新题集、原始报告和保存来源证明，且不能引入新的关键错误
或已有通过能力的实质退化。
连续两种实质方案无收益时停止该机制并重新定位。
评审先看请求、原始报告和来源，锁定内容判断，再看 Trace 与成本；
可盲评时盲评，否则标明。独立复核争议与通过结论，未解分歧不算通过。
助手评审不冒充用户或领域专家，不向默认链路加入 LLM 裁判。

小规模校准须在正式采集前固定评审操作：评审单位、严重性锚点、引用支持判定、盲评方式、
复核比例及分歧处理。正式集的全部报告按第 2 节评审，通过项、关键错误和不确定项按冻结
规则独立复核；记录评审者类型、实际复核覆盖与一致性。若只有助手评审，必须明示该限制，
不能声称已人工校准。未评审或未解分歧不计通过，保留单独状态；没有证据不能推成零错误。
评测侧模型裁判如以后获授权，须另计费用并经独立标注校准，不能直接以模型打分作为真值。

## 4. 正式评测指标、基线与交付

旧八场景与最终 24 次方案不作为当前评测协议，最终 24 仍封存。数据设计与工具核对可在
单例验证期间离线进行；真实校准和正式采集须分别满足路线阶段条件与明确授权。

### 4.1 指标与分母

所有指标附数据集/切分、版本、测量日期、代码/模型身份和 n/N。主表按每个独立 case 的首次
研究运行计算，节点内重试计入该次用量，重复性实验另表记录。设 N 为冻结计划例数、
S 为已派发例数、R 为取得原始报告例数、E 为完成语义评审例数；分别报告 N、S、R、E，
未执行例附原因。分母为零时记为不适用，不填零通过率或零错误率。正式集未完成时只发布阶段结果，
不能把成功子集当作整套验收。

| 指标 | 定义与限制 |
|---|---|
| 端到端有据回答可用率（主指标） | 满足第 2 节全部条件且无关键错误的原始报告数 / S。运行失败、未得报告、未审定均不计通过；另列 E/R 评审覆盖率 |
| 必答项有据覆盖率 | 每例获得适用来源支持的已回答必答项 / 冻结必答项数，再按预定类别权重汇总；明确未知的项不算已回答，不用字词命中计分 |
| 关键错误率 | 含至少一项关键错误的报告数 / E，同时列 E/R；无报告及未审定不是“零错误”，另报 / S 的已发现错误占比也不能冒称完整错误率 |
| 决定性论断支持率 | 充分得到适用来源支持的决定性事实论断 / 全部被审查的决定性事实论断；包括未引用论断，部分支持/不支持/未知分列。推论单独检查前提与适用范围，报告每例及汇总口径 |
| 运行完成与产物一致性 | 可查询完整结果的任务数 / S；保存/快照/展示/导出检查通过数及其检查分母另列。取得结果不等于内容通过 |
| 不确定性处理 | 按预先标注的可答/证据不足类别，报告恰当保留未知、无依据断言及过度弃答的数量/分母。诚实缺口不自动算满足必答项，也不自动判假 |
| 效率与资源 | 报告完成任务的研究墙钟 P50/P95 和样本数；另列所有任务的终态耗时、失败/超时，预加载及排队单列。报告实际 LLM/检索请求（含重试）、token、费用与预算拒绝；缺失用量或价格保留 unknown |
| 基线增益 | 同一未见题集上候选与简单基线的主指标、关键错误、延迟及资源差异；同时给出各自绝对值、分母和不确定性，不只给提升百分比 |

Top1 仅对预先可判定的推荐集合提供辅助指标，允许条件性答案；不得代替主指标。
现有 `report_quality.py` 的 A/B/C/D 是五项结构检查，来源绑定率也不等于论断支持率。
这些现有工具尚不能直接实现本节全部语义指标；需先核对采集/评审能力再正式测量。

### 4.2 公平比较与测量精度

- 预先冻结一个可解释的简单基线，例如同模型的检索后直接综合。明确基线的实际实现、
  输入与检索能力，不能将无检索基线的劣势全部归因于复杂工作流。可另做固定证据对照，
  但其结论只覆盖推理/综合，不与实时端到端评测混算。
- 配对比较使用相同问题、参考标准、模型版本与参数、供应商/来源政策、缓存及知识库政策、
  澄清/HITL 输入和可用预算上限；保留两边实际消耗。冻结运行顺序与时间窗口，控制来源更新
  和缓存预热影响；无法控制的差异明示，不把不同时期的历史运行冒称同期因果对照。
- 同时报告类别结果与预定权重的汇总结果。区间估计方法在运行前确定，相关变体按需求组
  处理；配对差异按 case/需求组计算不确定性，不能把一份报告的多个引用当作独立样本扩大 n。
  小类别样本不足须标明，不依据几个百分点的点估计直接宣布胜出。
- 重复性采用事先选定的子集与重复次数，每次调用都纳入预算；所有结果保留，报告波动，
  不择优取一次。唯一 case 数与研究运行次数分开，重复运行不增加独立 case 分母。

### 4.3 冻结与结论边界

正式采集前须具备：支持范围、样本/切分与去重记录、可复核参考标准、评分/独立复核规则、
基线和候选身份、每项指标计算方法、类别权重与区间方法、内容/关键错误/资源达标阈值、
重复性计划、实际运行器和授权总额度及停止线。目前不填未经同意的具体阈值、样本数或金额。
执行中保留所有原始结果；内容失败按冻结矩阵继续或结束，不能临时改规则筛掉低分。
仅完整执行且达到冻结标准才可称达标；未达标也交付真实测量结果及限制。
发布指标附最小脱敏证据与复算说明，旧 300-case、smoke-v1、开发单例及新正式集各自独立。

## 5. 运行、异常与记录

只在有实质候选或需排除关键假设时做付费开发测量；开发、校准、基线、正式采集及评审外呼均须被当前明确的总额度覆盖。授权应说明阶段、case 数、运行次数、重试/探测、每例与整批上限、身份及停止线，范围内不逐例请示。现代产品测量走 durable API 与隔离输出目录，不直接写生命周期表；恢复实验按单独冻结的旧接口记录，不能混为现代产品验收。正式采集先选定交付分支与实际运行器。每个 run 保持自身冻结预算政策；新增额度和准入精确登记，未知花费不写零。准备探测和研究成本分开。失败格不退款、不择优补跑。

普通内容失败进入缺陷分析；可归类的来源故障按预定矩阵记账并保留降级。安全、预算、租约/实例权威丢失、未知提交、身份漂移或未分类异常立即停止新准入并对账。记录数据集版本/hash、所有提交及未提交原因、run 状态、报告内容、保存来源、成本和独立复核。运行完成率用全部已提交为分母；内容可用率、关键错误、`unknown`、受限报告与外部故障分开报告。历史 300 例、smoke-v1、旧小样本和新开发结果不得混合分母。
