## 已确认事实与待验证假设

1. **预算扇出阻塞（已确认）**：serial-r1 的 11 个失败 run，停止后只读产品元数据的错误码均为 BUDGET_EXCEEDED_INSUFFICIENT_EVIDENCE。开发集 Trace 失败点在 conflict_detector。现有扫描最多并行 15 对，共享 helper 按消息 UTF-8 字节数 + 4,096 最大输出预留；失败时较多 token 仍为 reserved，而不是已消费。这不能解释为模型语义质量差。
2. **并发权限/租约失效（已确认分类，根因未确认）**：concurrent-r1 的 run 错误码为 RESEARCH_FAILED 10、预算证据不足 2；安全外呼分类含 StaleBudgetAuthorityError / budget_gate_failed。concurrent-r2 的健康检查返回 runtime_instance=lost，写接口返回 RUNTIME_INSTANCE_LEASE_LOST，故取消未成功；未绕过权限写数据库。事件循环延迟、数据库锁/事务竞争及心跳调度是后续诊断假设，不宣称已定位到具体实现或网络限流。
3. **评测恢复保护缺口（已确认）**：concurrent-r2 的产品公共事件类型有 run.auto_resumed 12、run.interrupted 13。服务自身可将有效检查点的中断 run 自动入队，采集器“不调用 resume”不足以禁止它；入队不是新的 LLM 派发证明。发现后关闭服务，无人为恢复/重试、无第二次 POST；11 个 queued 不是终态，不得按失败终态计数或重启原目录自动续跑。
4. **主机因素仍未排除**：最新 BugCheck 仍为 15:48，此轮没有新的蓝屏记录；不因此声称硬件稳定或排除主机负载影响。
