# O1：六源限流离线诊断与修复

日期：2026-09-17。范围：单进程内检索 provider 外呼控制，不是服务端入口限流或分布式调度。
本轮不调用真实检索/LLM、不读取保留集、不恢复历史实验或付费批次；研究额度仍为 43/48，剩余 5。
状态：本轮限流修复与离线验收完成；真实来源健康 `not_run`，O1 产品基线未完成。

## 缺口与修复入口

| 来源 | 原缺口 | 修复后的本地策略与覆盖范围 |
|---|---|---|
| arXiv | 只有并发门、无请求间隔；补证工具和探测绕过 | 3 秒间隔、1 在途；普通检索、scholarly 补证、路由 GET 探测共用门 |
| GitHub | 429/限流 403 只暂停当前调用；Retry-After 被截短；成功耗尽配额未处理 | 无 token 6 秒、有 token 2 秒间隔，2 在途；检索/探测共享冷却，区分权限 403 |
| Tavily | 初始桶允许突发；key POST 探测、429 重试绕过；锁内睡眠拖住其他 key | 每 key 12 秒、1 在途，无初始突发；POST 探测/所有重试共用门，429 原 key 等待，不借其他 key 绕过 |
| StackExchange | 40 秒队列不适合多 case；失败响应的 backoff/节流错误未共享；探测绕过 | 1 秒、1 在途；任意响应 body backoff、429、error_id=502 均反馈同一门 |
| 官方文档 | PyPI GET 无门，非 200 被静默跳过；安全 URL 检查可能将 429 当不可达 | PyPI 与动态文档检查分别 0.5 秒、2 在途；探测共享 PyPI 门；429 在 content-type 校验前反馈，失败保持可见 |
| ChromaKB | 本地库，不消费检索供应商请求额度 | 不添加网络限流；原本地检索保持，原生库/冷启动风险另行验证 |

这些数值是保守本地策略，不是最新官方配额承诺。Tavily 保留原 5/min 本地速率目标；凭证去重，
401/432 仍进入哈希耗尽池并可切换可用 key，等待后复查已失效 key；无密钥写入文档或日志。
Tavily 静态 HEAD 路由探测不含凭证；真正消费搜索请求的 key POST 已纳入。

## 等待、失败和兼容协议

- provider FIFO 准入跨 run、跨路由共享；受管搜索每次重试重新排队，等待不占在途许可，不持锁睡眠。
  每门最多 256 等待者、每次排队最多 600 秒；取消/超时释放位置和许可。状态不绑定旧事件循环。
- Retry-After 支持秒数/HTTP 日期；GitHub 同时考虑 reset，取较晚时间，不截短服务端冷却。
  冷却长于本次排队期限则明确失败，不提前发送；缺失/非法反馈使用有界重试及默认退避。
- 限流/本地准入失败不触发重新选路或附加探测；健康检查明确 degraded，路由可达不等于额度可用。
  self-forward 仅接收可选的三项配额响应头，旧 relay 未转发时只能退回本地策略。
- 官方动态 URL 门约束一次逻辑检查（含有界 redirect/HEAD fallback），不是逐物理跳计时。
  DNS 公网校验、固定 IP、每跳安全检查、内容与体积限制不变；排队之外网络总时限仍为 15 秒。
- 普通受管 HTTP 尝试最多 30 秒（社区 15 秒）；补证工具总时限从 20 改为 630 秒，包含所有排队、
  请求和重试，不是每次尝试 630 秒。较早的 run 取消/期限仍生效。
- 标准预算不变：900 秒 active 时间在预算准入检查，不是对已提交调用的自动定时取消。
  预算权威保持在原子 reserve_call：触顶后拒绝未提交的申请，但允许触顶前已提交的预留完成，
  provider 队列不重复轮询 latch 追溯取消它们。BudgetError 不被探测/回退吞掉；不新增预算额度。
  retrieval_calls/Trace 仍按逻辑检索/工具计数，不能拿它当物理 HTTP 尝试数。
- 已有 manifest schema v1 冻结工具总时限；旧 20 秒 manifest 历史可读但同 run 恢复不兼容，
  必须新建兼容 run。本轮不恢复原实验数据库，不改 migration/state schema/LLM Prompt。
- 保留 retrieve/search、github_rate 等所需入口及 v1 结果信封。GitHub 任一子查询失败时整个源
  标为 failed，不把残缺结果包装成 success；Tavily/官方回退扇出收齐在途子任务后再上抛失败。

## 验证与结论边界

修复前已离线复现：arXiv 跨 case 突发、Tavily POST 探测绕过、GitHub 120 秒反馈被截短。
测试覆盖排队/在途取消、超时/满队列、跨事件循环、探测/业务共享冷却、最后重试反馈、预算
latch、权限 403、非 HTML 429、工具入口和旧 manifest 兼容失败。独立复审指出本轮新增的
排队预算轮询违反“已提交预留不追溯取消”；真实 SQLite 回归先复现失败，再撤回该重复检查，
原子预算门本身没有修改。回归同时要求触顶后的新调用不发送、先前已预留的调用发送一次并结算。

另用真实六源适配器与模拟 HTTP/本地 KB 做 1 次单任务对照 12 个并发任务：只检查调度、
结果一致性和按比例缩短的请求间隔，不运行冻结产品 case，也不证明真实报告质量/外部配额充足。
最终验收（本机 Windows / Python 3.12.4，2026-09-17）：

- 代码/测试冻结后相关回归 **223 passed，57.89 秒**；完整套件 **1176 passed / 0 skipped，205.77 秒**。
  数值库 OMP/MKL/OpenBLAS 线程均设为 1；不是 Ubuntu/Python 3.11 的 CI 矩阵运行记录。
- smoke-v1 **12/12**，baseline 匹配，fingerprint 为
  `0e4dd8d574ea8554881eb7f39039e0a1131320f547b22e7cae382e83825ef919`；仅 fixture replay。
- pyflakes、vulture（100% confidence）、pip check、git diff --check 通过。
- 独立只读复审无剩余阻断项；其指出的预算重复检查、补证入口遗漏、非 HTML 429 和扇出收尾等
  已修正并覆盖。复审者未独立重跑测试，执行结果来自本轮实现验证。
- 上次中断后的扩展测试曾因 fixture URL 缺少文档路径而等待，本轮已修正并添加有界等待；

残余风险：服务商账号/IP 与其他进程共享配额、本地策略可能过于保守、排队增长可能耗尽原预算、
旧转发服务不返回配额头、动态 URL redirect/HEAD fallback 未逐物理跳 pacing、冷启动与 WHEA
硬件风险。本实现不协调跨进程配额，不保证 12-case
真实语义质量与单 case 相同；下一步应另行确认受控来源复测，付费整组仍暂停。
